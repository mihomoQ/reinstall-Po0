# Linux 源系统与完整重装验证

测试日期：2026-10-28（Asia/Shanghai）。候选脚本版本为 `PO0-20261028-4`。
测试硬件为同一台 PO0 x86_64/BIOS、2 vCPU、约 2 GiB RAM、20 GiB virtio 系统盘实例。
原始日志保存在操作员工作目录，不随公开仓库发布。

## 整机验证记录

| 源系统 → 目标系统 | 安装资源 | 当前结果 |
|---|---|---|
| Debian 12 → Debian 12 | 内网 Debian Installer/软件源 | 清盘安装、启动、公钥 SSH、APT、chrony 通过 |
| Debian 12 → Ubuntu 24.04.5 | Alpine 3.24 中间环境；南大 rsync 云镜像 | 镜像校验、落盘、启动、SSH、内网 APT、chrony 通过 |
| Ubuntu 24.04 → AlmaLinux 9.8 | Alpine 3.24；内网 HTTP 云镜像 | 镜像校验、XFS 安装、启动、SSH、启用的内网 DNF 源、chrony 通过 |
| AlmaLinux 9.8 → Ubuntu 22.04.5 | Alpine 3.24；南大 rsync 云镜像 | 镜像校验、落盘、启动、SSH、内网 APT、chrony 通过 |
| Ubuntu 22.04.5 → Debian 12 | 内网 Debian Installer/软件源 | 清盘安装、启动、SSH、APT、chrony 通过；测试机最终保留此系统 |

每个已通过的目标都从系统盘实际启动，通过原有操作员公钥登录；验证脚本检查 DHCP 默认路由、禁止 SSH 密码认证、软件包索引刷新、chrony 服务启用且活动、时间已同步，以及无失败的 systemd 单元。Ubuntu 的 systemd-resolved 本地 stub 正常使用 DHCP 上游 DNS。

五轮重装覆盖了四种系统作为源系统和目标系统的路径。测试过程中没有使用面板救援或面板重新安装。

## 执行路径

- 准备：Linux 源系统识别、磁盘和引导识别、完整 bundle 校验、资源与 SSH 公钥注入、GRUB 一次性启动。
- Debian：本地 preseed、DHCP、partman/debootstrap、内网 APT、chrony late hook、GRUB、自动首次启动。
- 云镜像：真实 Alpine 启动，`/configs` 与 `/po0-assets` 在 switch_root 后保留；元数据和空间检查、分区、单次整镜像下载、SHA256 与 QCOW2 检查、`install_qcow_by_copy`、扩容、目标网络/SSH/chrony/引导配置。
- 云镜像使用 `--hold 2` 在安装完成后检查目标配置和 SSH 主机公钥，再手动重启进入新系统。

## 边界

- AlmaLinux 默认镜像实际为 9.8，不是面板的固定 9.5 模板。
- 本轮硬件覆盖不包括 UEFI、ARM、多个磁盘或 IPv6 独立网卡。
- Gentoo 的内网快照、签名和二进制索引已探测可达，源配置及离线钥匙初始化有隔离测试；没有完成 Gentoo 整机安装。
- 其他发行版与 Windows 安装目标的入口保留，不代表它们均完成整机验证。Windows 作为源系统的入口已经删除。
- 压缩云镜像 RAM 缓存经过真实 BusyBox ash 小型镜像测试及隔离测试，本轮 Ubuntu/AlmaLinux 整机测试使用未包装的 QCOW2。
- 普通云镜像先重建分区再完整下载和校验，下载失败可能需要面板恢复；脚本不会承诺所有错误都在清盘前发现。
